# ADR-001：采用 SQLite + FTS5 作为默认存储与全文检索

## Context

RecallWeaver 面向需要嵌入 Python Agent 应用的本地记忆场景。核心数据包括文本记忆、时间有效区间和实体关系；部署希望不依赖独立数据库服务，数据应可随应用一起备份，并能在单机环境中完成查询。关键词检索需要支持倒排索引加速，同时项目需要保持安装和运维成本低。

## Options

1. **SQLite + FTS5**：使用 Python 标准库的 SQLite 驱动在本地保存结构化数据；以 FTS5 虚拟表和触发器维护全文索引。
2. **关系型数据库服务**：引入独立 PostgreSQL 等服务，获得客户端/服务端部署和更丰富的并发能力，但需要运维服务及网络连接。
3. **向量数据库或独立搜索服务**：增加语义相似度或专用搜索能力，但需要额外组件、数据同步和资源配置。
4. **仅在内存或文件中自行扫描**：部署简单，但缺少可靠事务、结构化查询和规模增长时的高效全文索引。

## Decision

采用 SQLite 作为默认持久化层，以 FTS5 为全文检索路径，并使用数据库触发器保持索引与 `memories.content` 同步。选择这一方案是因为它提供本地单文件持久化、事务与外键能力，且不要求 Docker、独立服务或重型运行依赖。FTS5 查询无结果或失败时，检索器使用 LIKE 子串查询作为兼容性兜底。现有方案定位为轻量关键词检索，不承诺向量语义检索能力。

## Consequences

- 安装与部署简单，数据库文件便于本地备份和迁移；基础读写无需网络服务。
- 数据和全文索引可在同一数据库事务模型内维护，减少外部索引同步组件。
- SQLite 的并发写能力和单文件锁定模型适合轻量本地工作负载，不等同于面向多节点高写入的数据库服务。
- FTS5 的 tokenizer 对语言和查询形式有影响；LIKE 兜底可提升兼容性，但大数据集上的扫描成本更高。
- 不提供向量相似度、分布式扩展或独立图数据库的能力；若未来场景要求这些能力，应以明确的规模和检索需求重新评估技术栈。
